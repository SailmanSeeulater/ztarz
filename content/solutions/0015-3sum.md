## The problem
Given an array of integers, return every distinct triple of values, taken from three different positions, that adds up to zero. The same set of three values must appear only once in the result, even if the array lets you build it in several ways.

For `[2, -3, 1, -1, 0, 1]` the answer is `[[-3, 1, 2], [-1, 0, 1]]`. The second 1 doesn't create a new triple.

## Thinking it through
1. **Restate.** Find all unique value triples `a + b + c = 0` using three different indices.
2. **Brute force.** Three nested loops, O(n³), plus a set of sorted triples to remove duplicates. Too slow, and the deduplication is clumsy.
3. **Reduce to a known problem.** Fix the first number `a`. Now I need two numbers that sum to `-a`. That is Two Sum, which I can solve in O(n) per `a`.
4. **Sort first.** Sorting costs O(n log n), which is cheaper than the O(n²) loop, and it gives two things: Two Sum on a sorted array becomes **two pointers** with O(1) extra space, and equal values sit next to each other so duplicates are easy to skip.
5. **Two pointers.** For each `i`, set `left = i + 1` and `right = n - 1`. If the sum is too small, move `left` right to get a bigger number. If it's too big, move `right` left. If it's zero, record it and move both.
6. **Skip duplicates in two places.** Skip `i` when `sorted[i]` equals the previous value, because it would find the same triples. After recording a match, move `left` past any copies of the value just used. (Moving `left` is enough: `right` then can't match the old value without a duplicate triple, and the sum check moves it along.)
7. **Early exit.** Once `sorted[i] > 0`, all three numbers would be positive, so no more zeros are possible.
8. **Edge cases.** Fewer than three elements: empty result. All zeros (`[0, 0, 0, 0]`): exactly one triple. No solution: empty result.

## Solution
```ts
function threeSum(nums: number[]): number[][] {
  const sorted = [...nums].sort((a, b) => a - b);
  const result: number[][] = [];
  for (let i = 0; i < sorted.length - 2; i++) {
    if (sorted[i] > 0) break; // three positives can't sum to 0
    if (i > 0 && sorted[i] === sorted[i - 1]) continue; // same anchor, same triples
    let left = i + 1;
    let right = sorted.length - 1;
    while (left < right) {
      const sum = sorted[i] + sorted[left] + sorted[right];
      if (sum < 0) left++;
      else if (sum > 0) right--;
      else {
        result.push([sorted[i], sorted[left], sorted[right]]);
        left++;
        right--;
        while (left < right && sorted[left] === sorted[left - 1]) left++;
      }
    }
  }
  return result;
}
```

## Complexity
- **Time:** O(n²). The outer loop runs n times and each two-pointer sweep is O(n); the O(n log n) sort is dominated.
- **Space:** O(1) extra beyond the sorted copy and the output. Sorting in place would avoid the copy, at the cost of changing the caller's array.

## Pitfalls
- Using `.sort()` without a comparator. JavaScript sorts as strings by default, so `-3` lands after `-1` and `10` before `2`.
- Skipping duplicates with `sorted[i] === sorted[i + 1]` on the anchor. That skips the first copy and loses triples like `[-1, -1, 2]`.
- Forgetting to move the pointers after a match, which loops forever.
