## The problem
Given an array of integers and a target, return every distinct set of four values, taken from four different positions, that adds up to the target. Each set of values should appear only once.

For `[2, 2, 2, 2, 2]` and target 8, the answer is a single quadruple, `[[2, 2, 2, 2]]`, even though there are five ways to pick the positions.

## Thinking it through
1. **Restate.** It's 3Sum with one more number and a target that isn't necessarily zero.
2. **Brute force.** Four nested loops, O(n⁴), plus deduplication. Far too slow.
3. **Peel off one number at a time.** Fixing one number turns 4Sum into 3Sum on the rest; fixing a second turns that into Two Sum. So: two nested loops for the first two numbers, then a two-pointer sweep for the last two.
4. **Sort first.** Same reasons as 3Sum: two pointers need sorted input, and sorting groups duplicates so they are easy to skip.
5. **Two pointers.** For fixed `i` and `j`, start `left = j + 1`, `right = n - 1`. Too small: move `left` up. Too big: move `right` down. Exact: record, then move both and skip copies of the `left` value.
6. **Duplicates at every level.** Skip `i` if it equals the previous anchor. Skip `j` if it equals the previous value *within this `i`* (`j > i + 1`), so `[2, 2, ...]` can still use two 2s as its first two numbers.
7. **Generalise.** The same idea gives k-Sum in O(n^(k-1)): recurse on fixed numbers until two remain, then use two pointers. Worth mentioning if asked for a follow-up.
8. **Edge cases.** Fewer than four elements: empty result. Large values: in JavaScript the sums of four values near 10⁹ stay exact (well under 2⁵³), but in Java or C++ they overflow a 32-bit int, so you'd need a 64-bit type there.

## Solution
```ts
function fourSum(nums: number[], target: number): number[][] {
  const sorted = [...nums].sort((a, b) => a - b);
  const n = sorted.length;
  const result: number[][] = [];
  for (let i = 0; i < n - 3; i++) {
    if (i > 0 && sorted[i] === sorted[i - 1]) continue;
    for (let j = i + 1; j < n - 2; j++) {
      if (j > i + 1 && sorted[j] === sorted[j - 1]) continue;
      let left = j + 1;
      let right = n - 1;
      while (left < right) {
        const sum = sorted[i] + sorted[j] + sorted[left] + sorted[right];
        if (sum < target) left++;
        else if (sum > target) right--;
        else {
          result.push([sorted[i], sorted[j], sorted[left], sorted[right]]);
          left++;
          right--;
          while (left < right && sorted[left] === sorted[left - 1]) left++;
        }
      }
    }
  }
  return result;
}
```

## Complexity
- **Time:** O(n³). Two nested anchor loops, each with an O(n) sweep; the sort is dominated.
- **Space:** O(1) extra beyond the sorted copy and the output.

## Pitfalls
- Skipping `j` duplicates with `j > 0` instead of `j > i + 1`, which drops quadruples that reuse the anchor's value.
- Copying 3Sum's `if (sorted[i] > 0) break`. The target can be negative, so that shortcut is wrong here.
- Integer overflow in languages with fixed-width ints.
