## Prompt

A client request fails. When do you return 400, when 422, and when 409?

## Answer

- **400 Bad Request:** the request itself is broken, so you can't even read it: JSON that won't parse, a malformed header, the wrong content type for the body.
- **422 Unprocessable Content:** the body parses fine but its values fail your rules: `email` isn't an email, `endDate` is before `startDate`.
- **409 Conflict:** the request is valid on its own but clashes with the resource's current state: that slug is already taken, or the item was archived while you edited it.

Plenty of good APIs use 400 for every validation error. What matters more is one documented convention, applied everywhere, with a body that says which field failed.
