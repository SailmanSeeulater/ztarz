## Prompt

Name the five SOLID principles with one line each.

## Answer

- **S, single responsibility:** a module has one reason to change.
- **O, open-closed:** open for extension, closed for modification; add behaviour without editing working code.
- **L, Liskov substitution:** code written against a base type keeps working when handed a subtype.
- **I, interface segregation:** clients shouldn't depend on methods they never call; prefer small interfaces.
- **D, dependency inversion:** depend on abstractions, not concrete implementations.

Robert C. Martin set out the principles; Michael Feathers coined the acronym. They're guidelines for keeping change cheap, not rules to apply everywhere.
